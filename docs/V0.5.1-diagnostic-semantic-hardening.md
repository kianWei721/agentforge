# V0.5.1 — Diagnostic Semantic Hardening

## 1. 为什么需要这个补丁

V0.5 第二次真实验收已经证明：

- Qwen 能自主选择 `query_device_status`、`query_device_properties`、`query_device_events`；
- 三个 Tool 都能通过真实 yudao HTTP Adapter 成功返回数据；
- LOW / read-only Policy 和 Governance 正常工作。

但真实回答暴露了一个严重的诊断语义问题：

```text
lastSeenAt = 2026-07-25T23:56:19Z
properties.observedAt(top-level) = 2026-07-26T01:17:45Z
```

模型把后者错误当成“本次查询时间”，因此给出约 1h21m stale 的结论。

实际上两个时间都是历史平台数据，并不是本次 Agent 查询时刻。

此外模型还对以下字段做了过强推断：

- `shadowStatus=CONFLICT` -> 推断配置同步被掉线中断；
- `SignalStrength=0` -> 倾向推断链路丢失；
- `PeripheralStatus` 全 0 -> 判断某时段“符合预期”；
- `events=[]` -> 容易泛化为没有告警/异常。

这些都超过现有 Tool 证据强度。

## 2. 修复原则

不修改 yudao。

AgentForge 在 Tool 层提供更明确、可计算的时间/语义字段，在 Agent Prompt 层限制因果推断。

## 3. Tool 时间语义

### query_device_status

新增：

```text
queriedAt
lastSeenAgeSeconds
```

其中：

- `queriedAt`：AgentForge 本次 Tool 执行时间；
- `lastSeenAt`：yudao 最后观测时间；
- `lastSeenAgeSeconds`：Tool 用确定性 Java 时间计算，不交给 LLM 猜。

### query_device_properties

原先顶层：

```text
observedAt
```

改成：

```text
queriedAt
snapshotUpdatedAt
snapshotAgeSeconds
```

各属性自己的 `observedAt` 保留，表示单个属性历史观测时间。

### query_device_events

新增：

```text
queriedAt
eventFeedSemantics = THING_MODEL_EVENT_HISTORY_NOT_ALARM_FEED
```

空结果额外返回：

```text
emptyMeaning = NO_EVENT_RECORDS_RETURNED_BY_THIS_QUERY
```

## 4. Agent 证据规则

IoT Diagnostic Agent V0.5.1 明确要求：

1. 只用 `queriedAt` 作为当前查询时间；
2. 优先使用 Tool 给出的 ageSeconds；
3. OFFLINE 可以作为事实，但不能直接推出具体掉线原因；
4. CONFLICT 只作为不一致状态，不解释具体原因；
5. SignalStrength/Temperature/PeripheralStatus 的 0 值没有质量语义时保持未知；
6. 空事件历史不等同于“没有告警”；
7. 最终回答分为：观测事实 / 支持的推断 / 证据不足。

## 5. 已存在 Agent 的安全升级

启动时只自动升级满足以下全部条件的旧 `iot-diagnostic`：

- version == 1；
- description 精确等于 V0.5 seed；
- systemPrompt 精确等于 V0.5 seed；
- toolNames 精确等于三个诊断 Tool。

因此如果用户已经通过 API 修改过 Agent（version 会增长，或内容不同），V0.5.1 不覆盖用户配置。

## 6. 验收

重新使用新 Session：

```text
Check whether device 373 has been operating normally recently.
Investigate using the available evidence and explain the basis for your conclusion.
```

必须确认：

- 三个 Tool 仍可自主调用；
- status 返回 `queriedAt + lastSeenAgeSeconds`；
- properties 返回 `queriedAt + snapshotUpdatedAt + snapshotAgeSeconds`；
- Agent 不再用 snapshotUpdatedAt 计算“当前离线时长”；
- Agent 不把 CONFLICT / SignalStrength=0 / events=[] 直接转成因果事实。
