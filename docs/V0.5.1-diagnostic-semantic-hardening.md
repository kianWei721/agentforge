# V0.5.1 — Diagnostic Semantic Hardening

## Problem

A technically successful tool call can still produce an unsafe answer if the model overstates what the returned data proves.

V0.5.1 hardens the semantic contract between adapters, tools and the final Agent response.

## Rules

### Status

`status` is an observed backend fact only for the time represented by the response.

### Property snapshot

Saved properties expose snapshot semantics. Stale values must not be presented as current live telemetry.

### Event history

An empty event list means:

```text
NO_EVENT_RECORDS_RETURNED_BY_THIS_QUERY
```

It does not imply that no alarms, incidents or failures occurred in some other feed.

### Knowledge

Static knowledge is guidance, not runtime fact:

```text
Knowledge hit != confirmed device condition
Knowledge suggestion != root cause proof
```

## Final-answer contract

The diagnostic Agent should separate:

1. observed facts;
2. knowledge-backed troubleshooting guidance;
3. unresolved unknowns.

When evidence is insufficient, the correct answer is `UNKNOWN`, not a plausible guess.
