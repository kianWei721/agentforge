# V0.3 Persistence Infrastructure

## Scope

本阶段只处理 MySQL Agent 持久化、Redis 基础接入和本地 Docker Compose。

Session、Message、Execution、Trace 和真实 IoT Adapter 暂不在本次范围。

## Persistence boundary

领域层继续只依赖 AgentDefinitionRepository；MySQL/JDBC 实现在 agentforge-infrastructure，避免基础设施依赖反向进入领域层。

## Tables

af_agent 保存 Agent 核心定义、模型配置、启停状态和版本。

af_agent_tool 保存 Agent 与 Tool 的绑定关系，并通过外键级联删除。

## Concurrency

更新 Agent 使用 WHERE id = ? AND version = ? 做乐观版本校验；旧版本被其他请求抢先更新时，本次更新失败，避免静默覆盖。

## WebFlux and JDBC

当前平台是 Spring WebFlux，而 JDBC 是阻塞 I/O。Controller CRUD、System Health、Runtime 首次加载 Agent Definition 都调度到 Reactor boundedElastic，避免阻塞 Netty EventLoop。

本阶段不为了形式把整个领域接口改成 Reactive Repository；后续如果 Agent 管理出现高并发，再评估 R2DBC。

## Redis role

Redis 当前只完成连接配置和健康探测。Agent Definition 仍以 MySQL 为事实数据源。

## Local ports

MySQL 容器 3306 映射到宿主机 3307；Redis 容器 6379 映射到宿主机 6380，以减少与开发机现有服务冲突。

## Verification

依次执行：

    .\scripts\start-infra.ps1
    .\scripts\mvn.ps1 clean test
    .\scripts\run-dashscope.ps1

然后检查 /api/v1/system/health，预期 version=0.3.0-SNAPSHOT、mysql=UP、redis=UP。

最后创建一个 Agent，记录 id，重启 AgentForge，再 GET 该 id；重启后仍能查到即证明 MySQL 持久化闭环。
