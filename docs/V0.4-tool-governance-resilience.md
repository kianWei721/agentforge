# V0.4 — Tool Governance & Resilience

## Goal

V0.4 moves AgentForge from “the model can call a tool” to “the runtime can govern, audit and safely block a tool invocation.”

All device identifiers, command receipts and backend examples in this public document are synthetic.

## Failure governance

```text
Tool Call
  -> Policy
  -> Governance
  -> Business Tool
  -> Outbound Adapter
  -> Tool Result
  -> Durable Trace
```

A Tool result exposes machine-readable semantics:

```text
failureCode
retryable
governanceDecision
governanceReason
outboundAttempts
outboundOutcome
```

Repeated calls with equivalent arguments can be blocked after a non-retryable failure. A blocked call records `outboundAttempts=0`.

## Risk policy

Tools expose:

```text
readOnly
riskLevel = LOW | MEDIUM | HIGH
```

Baseline policy can return:

```text
ALLOW
DENY
REQUIRE_CONFIRMATION
```

Read-only low-risk tools are allowed by default. Write tools are high-risk and require confirmation.

## Durable confirmation

Confirmation lifecycle:

```text
PENDING -> APPROVED -> CONSUMED
        -> REJECTED
        -> EXPIRED
```

A confirmation is bound to:

```text
agent
user
session
tool
argument fingerprint
```

Approval does not directly execute the tool. The next fully matching invocation atomically consumes the authorization permit.

## Restricted demo write tool

The repository contains a disabled-by-default demo write tool:

```text
set_lure_lamp_state
demo deviceId = 1001
demo productId = 2001
target = ON | OFF
```

The identifiers above are synthetic. The implementation demonstrates:

- fixed allowlist boundary;
- execution-time device/product/online precheck;
- target-state semantics over a toggle-style backend;
- no automatic retry of an ambiguous mutation;
- read-only post-write verification;
- explicit `statePersistenceGuaranteed=false`.

Synthetic command receipts use values such as:

```text
commandId = 9001
messageId = demo-message-1
```

## Audit semantics

A high-risk write attempt can be reconstructed from durable trace fields including:

```text
toolCallId
riskLevel
policyDecision
confirmationId
confirmationStatus
governanceDecision
outboundAttempts
httpStatus
businessCode
outboundOutcome
failureCode
retryable
```

This slice is about governance semantics, not a specific production IoT implementation.
