# V0.6.2 — Embedding + Elasticsearch Hybrid Retrieval

## 1. 目标

V0.6.1 已证明 Knowledge Grounding 语义链成立，但真实验收出现：

```text
中文 query -> 英文知识
LEXICAL_V1 miss

英文 query -> 英文知识
LEXICAL_V1 hit
```

V0.6.2 用语义向量解决跨语言/同义表达召回，同时保留 BM25 对精确术语、型号、字段名的优势。

## 2. 架构

```text
MySQL af_knowledge_document / af_knowledge_chunk
          |
          | rebuild
          v
DashScope text-embedding-v4
          |
          v
Elasticsearch
  - title/content -> BM25
  - embedding     -> dense_vector cosine kNN
          |
          +---- lexical ranked list
          +---- vector ranked list
                    |
                    v
             Java RRF fusion
                    |
                    v
           HYBRID_ES_RRF_V1
                    |
                    v
            search_knowledge
```

MySQL 是 Source of Truth。Elasticsearch 是 Derived Index，可删除并从 MySQL 全量重建。

## 3. Embedding

默认：

```text
provider   = DashScope OpenAI-compatible embeddings
model      = text-embedding-v4
dimensions = 1024
batchSize  = 10
```

API Key 默认复用 `DASHSCOPE_API_KEY`。

Embedding endpoint 默认：

```text
https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings
```

生产环境可以配置 Model Studio workspace-specific compatible-mode base URL。

## 4. Elasticsearch Mapping

索引默认：

```text
agentforge-knowledge-v1
```

核心字段：

```text
documentId  keyword
chunkId     keyword
chunkIndex  integer
title       text
sourceType  keyword
sourceRef   keyword
content     text
embedding   dense_vector(dims=1024, similarity=cosine)
```

## 5. 两路召回

### BM25

```text
multi_match:
  title^2
  content
```

用于：

- productId / 型号；
- 属性 identifier；
- 故障码；
- 手册中的精确术语。

### Vector kNN

Query 文本先生成同模型同维度 embedding，然后对 `embedding` 做 kNN。

用于：

- 中英跨语言；
- 同义改写；
- 自然语言问题与手册表达不一致。

## 6. RRF

两路分别取候选后按 RRF 融合：

```text
score(d) = Σ 1 / (rrfK + rank(d))
```

默认：

```text
rrfK = 60
candidateMultiplier = 4
```

不直接混合 BM25 raw score 与 cosine raw score，避免不同评分尺度互相污染。

## 7. 配置

```powershell
.\scripts\configure-rag.ps1
```

Hybrid 默认关闭，因此升级代码不会要求本地立刻存在 Elasticsearch。

配置完成并重启后，Health 应出现：

```text
milestone = V0.6.2-hybrid-retrieval
knowledgeHybridEnabled = true
knowledgeHybridConfigured = true
knowledgeRetrieverMode = HYBRID_ES_RRF_V1
knowledgeEmbeddingModel = text-embedding-v4
knowledgeEmbeddingDimensions = 1024
```

## 8. Rebuild

首次启用 Hybrid 或知识发生变化后执行：

```http
POST /api/v1/knowledge/index/rebuild
```

流程：

1. 从 MySQL 读取 enabled chunks；
2. 按 batch 生成 embeddings；
3. 删除并重建 Elasticsearch derived index；
4. bulk index；
5. refresh；
6. 返回 indexedChunks / model / dimensions / duration。

V0.6.2 采用显式 rebuild，避免 MySQL 写成功但 ES 写失败形成伪事务。
后续可以演进 Outbox + async incremental indexing。

## 9. 验收

使用 V0.6.1 已存在的英文 TEST 文档，直接中文查询：

```text
设备长期离线应该按什么顺序排查？
```

要求：

- `retrievalMode = HYBRID_ES_RRF_V1`；
- 不需要模型先翻译成英文；
- 中文 query 能召回英文 TEST 文档；
- citationId 保持 `KB:{documentId}#{chunkIndex}`；
- Agent Grounding 规则保持不变；
- TEST 文档不能升级为真实根因。

## 10. 边界

本阶段不做：

- PDF/Word 自动解析；
- OCR；
- Outbox 增量索引；
- Cross-Encoder Reranker；
- Knowledge ACL / tenant isolation；
- Citation UI。

这些在 Hybrid 基础设施稳定后继续演进。
