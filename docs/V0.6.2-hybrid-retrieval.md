# V0.6.2 — Embedding + Elasticsearch Hybrid Retrieval

## 1. 目标

V0.6.1 已证明 Knowledge Grounding 语义链成立，但真实验收出现：

```text
中文 query -> 英文知识
LEXICAL_V1 miss

英文 query -> 英文知识
LEXICAL_V1 hit
```

V0.6.2 用语义向量解决跨语言/同义表达召回，同时保留 BM25 对精确术语、型号、字段名的优势。

## 2. 架构

```text
MySQL af_knowledge_document / af_knowledge_chunk
          |
          | rebuild
          v
DashScope text-embedding-v4
          |
          v
Elasticsearch
  - title/content -> BM25
  - embedding     -> dense_vector
          |
          +---- lexical ranked list
          +---- vector ranked list
                    |
                    v
             Java RRF fusion
                    |
                    v
           HYBRID_ES_RRF_V1
                    |
                    v
            search_knowledge
```

MySQL 是 Source of Truth。Elasticsearch 是 Derived Index，可删除并从 MySQL 全量重建。

## 3. Elasticsearch 版本兼容

AgentForge 自动读取 Elasticsearch 根接口中的 `version.number`。

### Elasticsearch 8+

向量字段使用：

```text
dense_vector
index = true
similarity = cosine
```

召回使用 indexed approximate kNN。

### Elasticsearch 7.17.x

Elasticsearch 8.0 之前没有 indexed approximate kNN，因此 Mapping 只保存：

```text
dense_vector(dims=N)
```

向量召回使用：

```text
script_score
cosineSimilarity(params.query_vector, 'embedding') + 1.0
```

即精确线性扫描。

所以测试环境 `7.17.24` 可以直接用于 V0.6.2，不要求升级 ES。

代价是向量召回复杂度随 Chunk 数线性增长。当前 V0.6 验收和小规模知识库可接受；大规模生产知识库应使用 Elasticsearch 8+ indexed kNN。

无论 7.x / 8.x，上层都是：

```text
BM25 + Vector + Java RRF
```

`KnowledgeRetriever` 和 `search_knowledge` 接口保持不变。

## 4. Embedding

默认：

```text
provider   = DashScope OpenAI-compatible embeddings
model      = text-embedding-v4
dimensions = 1024
batchSize  = 10
```

API Key 默认复用 `DASHSCOPE_API_KEY`。

## 5. Rebuild

首次启用 Hybrid 或知识发生变化后执行：

```http
POST /api/v1/knowledge/index/rebuild
```

流程：

1. 检测 ES major version；
2. 从 MySQL 读取 enabled chunks；
3. 按 batch 生成 embeddings；
4. 删除并重建 ES derived index；
5. 根据 ES 版本创建兼容的 dense_vector Mapping；
6. bulk index；
7. refresh。

## 6. 验收

测试环境：

```text
Elasticsearch = 192.168.30.103:9200
version       = 7.17.24
```

应使用：

```text
vector mode = EXACT_SCRIPT_SCORE_COSINE
retrieval   = BM25 + exact vector + RRF
```

然后使用 V0.6.1 已存在的英文 TEST 文档，直接中文查询：

```text
设备长期离线应该按什么顺序排查？
```

要求：

- `retrievalMode = HYBRID_ES_RRF_V1`；
- 中文 query 能召回英文 TEST 文档；
- citationId 保持 `KB:{documentId}#{chunkIndex}`；
- Agent Grounding 规则保持不变。

## 7. 当前边界

Elasticsearch 7.17 的 exact vector scan 适合 V0.6 和小规模知识库，不应误认为生产级 ANN。

后续生产化路线：

```text
ES 8+
-> indexed dense_vector
-> HNSW / approximate kNN
-> large-scale retrieval
```
