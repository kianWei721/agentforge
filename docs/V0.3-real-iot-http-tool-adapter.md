# V0.3 — External IoT HTTP Tool Adapter

## Goal

V0.3 connects the existing `DeviceStatusQueryPort` to an external HTTP backend without exposing credentials or backend-specific details to the model.

All endpoint paths, device IDs, product IDs, timestamps, command IDs and payloads in this public document are **synthetic examples**.

## Public demo contract

```http
GET /api/iot/devices/{deviceId}
Authorization: Bearer <access-token>
tenant-id: <tenant-id>
```

Example response:

```json
{
  "code": 200,
  "data": {
    "deviceId": 1001,
    "state": "ONLINE",
    "lastReceiveTime": 1788000000000,
    "productId": 2001
  }
}
```

The adapter maps backend data into the smaller runtime contract:

```text
deviceId
status
lastSeenAt
source
safe attributes
```

## Security boundary

The LLM cannot provide or override:

- backend base URL;
- access token;
- tenant header;
- network timeout configuration.

Credentials come from local/deployment configuration only. Tool results and trace metadata must not contain tokens, backend URLs or raw error bodies.

## Failure semantics

HTTP and business-level status codes are normalized into machine-readable categories such as:

```text
AUTHENTICATION_FAILED
FORBIDDEN
BAD_REQUEST
BACKEND_UNAVAILABLE
TIMEOUT
INVALID_RESPONSE
```

Each failure also carries an explicit `retryable` flag.

## Resilience

Read-only HTTP requests support bounded retry and a simple circuit breaker. Blocking calls are isolated from reactive event-loop threads.

## Configuration

The default mode is `demo`. External HTTP mode is opt-in:

```text
AGENTFORGE_IOT_DEVICE_STATUS_MODE=http
AGENTFORGE_IOT_BASE_URL=https://iot.example.internal
AGENTFORGE_IOT_ACCESS_TOKEN=<secret>
AGENTFORGE_IOT_TENANT_ID=1
```

Public-safe default paths are configurable:

```text
/api/iot/devices/{deviceId}
/api/iot/devices/{deviceId}/details
/api/iot/devices/{deviceId}/events/history
```

Never commit real credentials or private infrastructure addresses.
